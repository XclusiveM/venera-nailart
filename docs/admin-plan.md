# Управление содержимым Венера NAILART

## Состояние внедрения
Первый этап: данные услуг извлечены в `data/services.json` без изменения действующего сайта. **Этот файл пока не является источником данных для страниц и калькулятора.** Не редактируйте цены только в нём, пока не завершена миграция.

## Контракт каталога
- `schemaVersion` — версия структуры данных.
- `categories` — категории с постоянными идентификаторами.
- `services` — услуги: `id`, `cat`, `name`, `price`, `min`, `note`, `status`.
- `extras` — дополнительные опции; `from: true` означает цену «от».
- `price: null` — цена не установлена, **не ноль рублей**.
- `status: published` — опубликовано; будущие статусы `draft`, `hidden`, `archived`.
- Идентификаторы `id` не менять при переименовании.

## Обязательные условия до запуска админ-панели
1. Перевести страницы и калькулятор на единый каталог с проверкой структуры данных.
2. Исключить дублирование цен в HTML и других файлах; предусмотреть SEO-страницы, которые генерируются при публикации.
3. Добавить безопасную авторизацию через серверный компонент, разграничение ролей и аудит изменений. GitHub Pages не предоставляет серверной авторизации.
4. Проверять цену, длительность, обязательные поля, уникальность ID и совместимость услуг до публикации.
5. Сохранять черновики, подтверждать успешное развёртывание, поддерживать откат версии.
6. Для фотографий: оптимизация, проверка типа и размера, учёт использования изображения на разных страницах.
7. Интеграции аналитики включать отдельно, с настройками согласия; не разрешать произвольный JavaScript через админку.
8. Не менять `noindex,nofollow` без разрешения владельца.
9. Проверить весь публичный сайт, мобильную версию, калькулятор и ссылки до релиза.

## Принцип интерфейса
Полностью русский интерфейс, крупные элементы управления, доступность с телефона. Основные разделы: «Услуги и цены», «Фотографии», «Страницы», «Продвижение», «Настройки», «История изменений».
